# れしぴょん（recipion）

日本の家庭料理向けに、**レシピ・買い物メモ・在庫**をつなぐ Web アプリ（PWA）です。個人で企画から運用まで行っています。

**<https://recipion.app>**（買い物メモは、ログインなしで試せます）

## 作った理由

レシピ・買い物メモ・在庫を、すべて汎用のメモアプリに書いていました。ほかのメモに埋もれてレシピを探しにくく、「売っていたら買う、なければ別の物」という条件つきのメモも書けず、在庫はときどきまとめて直すしかありませんでした。料理のための1本の流れとして、つなげることにしました。

## できること

- **買い物メモ**：ログインなし・オフラインで使えます。「1袋」「1パック」と自由な単位で書け、条件つきのメモも作れます。
- **在庫**：購入を確定すると、在庫の単位（g・本など）に換算して入ります。買った日・期限の違う分（ロット）ごとに管理し、期限の近い分から使います。
- **レシピ**：本文を1つの入力欄に書くと、材料と分量を読み取ります。足りない材料は買い物メモへ。「作った」で、使った分を在庫から引きます。
- **公開**：レシピを公開でき、ほかの人のレシピを検索できます。

## 工夫した点

- **公開前の審査**：不適切な語の一覧と、Workers AI（Gemma）の文脈の判定の二段です。AI は誤る前提で、怪しい文章は管理者の画面に回し、AI が使えないときは公開を止めます。悪い文章から無作為に抜き取った700件で、86%を止め、4.6%を通しました。良い文章1,103件のうち、誤って止めたのは1件です（`moderation-eval/`）。
- **日本語入力に対応した補完**：変換中の動きはブラウザと OS ごとに違うため、実機でイベントの順番を記録し、環境ごとに3つの方式を使い分けています。取り消しの履歴も自前で持っています。
- **買った単位を、在庫の単位に直す**：「食材 × 単位」ごとに換算を記憶します。換算のもとになる重さなどの値は、出典を確かめたものだけを使い、確かめられない値には「約」を付けます。
- **運営費をほぼ0円に**：ログインが前提の画面は、ビルド時に作った静的な HTML で配信し、サーバー（Worker）を起動しません。アプリにない URL への bot のアクセスは、WAF で止めます。

## 技術

| 領域 | 使用技術 |
|---|---|
| フロントエンド | React 19、TanStack Start / Router、TypeScript、Vite、vanilla-extract、Dexie（IndexedDB）、自前の Service Worker |
| バックエンド | TanStack Start のサーバー関数、Drizzle ORM、PostgreSQL（Neon）、Better Auth（メールの6桁のコードでログイン） |
| インフラ | Cloudflare Workers、Hyperdrive、Workers AI、WAF、Turnstile、Access |
| 品質 | Vitest（jsdom と Chromium）、Playwright、Biome、GitHub Actions |

## 開発の進め方

- 実装は AI（Claude Code）と進めています。何を作るか、どう設計するか、何をテストで守るかは自分で決め、実機で確かめています。
- テストは 2,600件以上（jsdom と実際の Chromium）。CI で、lint・型・テスト・ビルドを、push のたびに確かめています。
- 機能は `src/features/<機能>/` に、`domain`（規則）・`application`（ユースケース）・`infrastructure`（DB）・`server`（サーバー関数）・`components`（UI）の層に分けています。

手元で動かす方法・設計の約束・デプロイは、[DEVELOPMENT.md](DEVELOPMENT.md) にあります。
