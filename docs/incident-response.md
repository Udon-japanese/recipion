# 情報漏えいなどが起きたときの対応手順

個人情報（メールアドレス・表示名・ハンドル・レシピなど）が、漏えい・滅失・毀損した（または、そのおそれがある）ときの、手順。
プライバシーポリシーに書いた約束（原因を調べる／利用者に連絡する／法令に従って個人情報保護委員会に届け出る）を、実行するためのもの。専門家の確認は、受けていない。

> 期限などの数字は、**個人情報保護委員会の公式の資料（ガイドライン通則編、漏えい等報告のページ）で、その時点の内容を確認すること。** 以下は、調べた時点（2026-10-12）の目安。

## 1. 気づいたら、まず（その日のうちに）

1. **被害を止める**（原因が分かる前でも、先に止める）。
   - 疑わしい秘密の値を、入れ替える：`RESEND_API_KEY`、`TURNSTILE_SECRET_KEY`、Neon の接続（パスワードの再発行）、Cloudflare の API トークン。
   - **`BETTER_AUTH_SECRET` は、安易に変えない**（変えると、全員のログインが切れ、限定公開のパスフレーズが読めなくなり、永久停止の記録が効かなくなる）。ただし、**それ自体が漏れたときは、変える**（影響を覚悟のうえで）。
   - 全員を、ログアウトさせたいときは、DB の `session` を削除する。
   - 必要なら、Worker を、`nlx --local wrangler rollback` で戻す、または、一時的に止める。
2. **記録を残す**：いつ・何が・どこで起きたか、分かっていること・分からないこと。画面や、ログ（Workers Logs）の保存。
3. **何が漏れたかを、確定する**：どのテーブルの、何件・誰の、どの項目か。

## 2. 個人情報保護委員会への報告が要るか

次のいずれかに当たる（またはそのおそれがある）とき、**報告が必要**（個人事業主でも、同じ）。

- 要配慮個人情報が含まれる。
- 財産的な被害が生じるおそれがある（クレジットカード番号など。このサービスは、取り扱っていない）。
- **不正の目的によるおそれがある**（不正アクセス、外部からの攻撃、内部の者による持ち出しなど）。**このサービスでは、不正アクセスによる漏えいは、件数に関わらず、報告が必要と考える。**
- 1,000人を超える。

報告の方法・期限（目安）：

- **速報**：知ったときから、概ね **3〜5日以内**。
- **確報**：**30日以内**（不正の目的によるおそれがある事態は、**60日以内**とされていると理解している。公式の資料で、必ず確認する）。
- 窓口：個人情報保護委員会のウェブサイト（漏えい等報告のフォーム）。

> 委託先（Cloudflare・Neon・Resend）で漏えいが起きたときは、委託元（このサービス）が、報告する形になる。委託先から連絡が来たら、その日付が「知ったとき」。

## 3. 利用者への連絡

- 影響を受けた利用者に、**速やかに**、次の内容を連絡する：何が起きたか／漏れた情報の項目／分かっている原因／利用者が取れる対策／問い合わせ先（`contact@recipion.app`）。
- 連絡の手段：ログイン用のメール（Resend）。メールを送れないときは、ログインのページに、お知らせを掲載する。

## 4. そのあとで

- 原因の調査と、再発の防止（設定・コード・手順の見直し）。
- 必要なら、プライバシーポリシーの記載を直す（「最終更新日」を更新）。
- この手順書を、実際に起きたことに合わせて、直す。
